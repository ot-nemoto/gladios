# 装備室の引き継ぎ

Muse・Claudeなどへ、現在の「小さな装備室」の拡張を依頼するための実装案内。開発規則の正本は [development.md](development.md)。装備室の決定事項は [基本設計書](01_ゲーム企画・基本設計書.md) の本文と §14 を読む。この資料は新しい機能の採用を決めるものではない。

## 現在できること

[公開ページ](https://ot-nemoto.github.io/gladios/)の現在の操作と初期表示は [基本設計書 §2](01_ゲーム企画・基本設計書.md#2-現在の仕様) を参照。

独立した兜・武器・防具を重ねる仕組みはまだない。新しい組み合わせを増やす場合、全身画像を増やす方法とパーツ合成を導入する方法は別の変更になる。今回の低頭身は装備室の表現で、戦闘ゲーム本体の頭身を変更したものではない。

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `index.html` | 公開ページの入口、選択ボタン・説明・Canvas |
| `src/dress-up.ts` | 画像読込、切替、位置合わせ、PNG保存 |

`src/main.ts`・`sample-*.ts`・`motion-samples.ts`・`style.css` は旧棒人間サンプル用。現在の入口からは読み込まない。`work/` のローカル試作は配布・実行に不要。[過去資料](archive/README.md) は旧戦闘構想・試作の記録で、現在の装備室の仕様・作業指示として転用しない。

## 画像と表示位置

素材は `src/assets/dress-up/` の `base.png`・`silver-teal.png`・`black-gold-purple.png`・`gold-red.png`。位置合わせの現在値は `src/dress-up.ts` の `variants`、拡大率と座標の計算は `select()` 内の描画処理を参照する。`waist` は元PNG内の腰の基準点、`feet` は足裏の基準Y。元画像を変形保存せず、描画時に位置と大きさを調整する。数値を変更するときはソースを正とする。

画素密度や接地基準の統一方法は [#105](https://github.com/ot-nemoto/gladios/issues/105) の検討事項で、解決済みではない。

保存するPNGは位置合わせ後のCanvasではなく元画像。画像生成のAPIキーや、他サービスのログインは含まない。既存画像を表示するだけなら画像生成サービスは不要。

### 全身画像の候補を1つ追加するときの確認箇所

これは拡張依頼があった場合の実装案内であり、追加自体は今回行わない。

1. 全身PNGと縮小サムネイルを、それぞれ上記ディレクトリへ追加する。
2. TSの画像import、`Style`、`styles`、`variants` を更新する。固有ID・名称・説明・代替テキスト・腰と足裏の基準を揃える。
3. ボタンのイベント処理にある `base / silver / purple / goldred` の判定にも新IDを追加する。
4. HTMLの `button[data-style]` とサムネイルを追加し、`4 STYLES`・初期カウンター `02 / 04`、本文・メタ情報など件数を含む文言を確認する。TSの初回読込失敗時の `— / 04` も更新する。サムネイルの `img` の `width` / `height` は、その画像の縦横比と一致させる（現在は元PNGの寸法を指定）。
5. 他の画像とキャラクターの体格・服装・向き・絵柄・位置が揃うか比較する。現在の承認済み画像を参照し、未依頼の描き直しやエフェクト追加まで広げない。

全身PNGはTSからimportし、サムネイルはHTMLでViteが処理するパスを使っている。配信先の `/gladios/` を壊す固定URLを追加しない。

## 起動と確認

Node.js 24。リポジトリ、またはZIP展開後の `gladios/` で実行する。

```sh
npm ci
npm run dev
```

開発画面は `http://localhost:5173/`。型検査と通常ビルドは次の通り。

```sh
npm run typecheck
npm run build
```

GitHub Pagesのサブパスも確認する場合は、次のビルドでdistを置き換えてからpreviewを起動する。

```sh
npm run build -- --base=/gladios/
npm run preview -- --base=/gladios/ --host 127.0.0.1 --port 4173 --strictPort
```

確認URLは `http://127.0.0.1:4173/gladios/`。ルートURLでの通常previewへ戻す際は、一度previewを停止し、`npm run build` で通常のdistを作り直してから `npm run preview` を起動する。ポート使用中なら別のポートを指定する。developへマージすると公開ワークフローが実行される。

検証結果の記録方法は [開発ガイド](development.md) を参照。装備室の基本確認の例は以下。

- 初期画像、全候補への切替、兜を外す、名称・選択表示が一致する。
- 保存したPNGが選択中の元画像と一致する。
- 素早く切り替えても古い読込結果へ巻き戻らない。
- 画像読込失敗時にエラーを表示し、直前の表示・保存先を維持する。初回失敗なら保存できず、再選択で再試行できる。
- TabとEnter/Spaceで操作でき、選択ボタンの `aria-pressed` とCanvasの説明が更新される。
- 狭い画面でも操作でき、Pages用ビルドで画像の404がない。

ブラウザ確認にはPlaywrightを利用できる。現時点でリポジトリにPlaywrightのテスト環境は同梱していない。表示済みのIDは `canvas.dataset.style` で確認できる。未検証事項は実施済みと扱わない。

## 他のLLMへの渡し方

### リポジトリを開けるエージェント

[GitHubリポジトリ](https://github.com/ot-nemoto/gladios)のdevelopを開き、[依頼テンプレート](装備室_依頼テンプレート.md) に今回の変更を記入して渡す。作業環境にはGit・Node.jsが必要。PR操作にはGitHubの権限とgh、規定のレビューには認証済みClaude Codeが必要になる。`AGENTS.md` / `CLAUDE.md` の自動読込対応は環境によるため、依頼文にも読むファイルを明記している。

### ファイル添付を受け付けるWebチャット

下記の共有用ZIPと、記入済みの依頼テンプレートを渡す。ZIPを展開・読解できるかはそのサービスによる。まず変更案や差分を受け取り、リポジトリを操作できる環境で適用・確認する。ZIPにはGit履歴がないため、それだけで元リポジトリへのPRを作れるものではない。過去の経緯が必要ならGitHub上のIssue・PR・履歴も参照する。

共有用ZIPは、**共有したいコミットがHEADでありGitHubへpush済みであることを確認し、追跡済みの内容から**作る。未コミットの変更は含まれない。develop以外から共有する場合は、そのブランチ名またはPRのURLも伝える。

```sh
mkdir -p work/handoff
git archive --format=zip --prefix=gladios/ --output=work/handoff/gladios-wardrobe-handoff.zip HEAD
git rev-parse HEAD
```

コード・画像・資料・ロックファイルを含む。`.git`、`node_modules`、未追跡の添付ZIPや作業ファイルは含まれない。新たに認証情報を追加して共有しない。ZIPと一緒に出力されたコミットIDを伝えると、渡した時点を特定できる。

この資料の用意は、他サービスへの接続やアカウント権限の設定まで行うものではない。拡張したい内容は、次の依頼で小さく指定する。
