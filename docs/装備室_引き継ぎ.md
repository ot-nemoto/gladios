# 装備室の引き継ぎ

Muse・Claudeなどへ、現在の「小さな装備室」の拡張を依頼するための実装案内。開発規則の正本は [development.md](development.md)。装備室の決定事項は [基本設計書](01_ゲーム企画・基本設計書.md) の本文と §14 を読む。この資料は新しい機能の採用を決めるものではない。

## 現在できること

[公開ページ](https://ot-nemoto.github.io/gladios/)の現在の操作と初期表示は [基本設計書 §2](01_ゲーム企画・基本設計書.md#2-現在の仕様) を参照。

元の画像切替版 `/` と、比較用の装備着脱版 `/equipment.html` がある。着脱版では共通人物と独立した兜6種類を合成する。武器・防具の着脱はまだない。今回の低頭身は装備室の表現で、戦闘ゲーム本体の頭身を変更したものではない。

## 画像と表示位置

素材は `src/assets/dress-up/` の `base.png`・`silver-teal.png`・`black-gold-purple.png`・`gold-red.png`・`silver-horned.png`・`gold-single-horn.png`・`black-red-crest.png`。位置合わせの現在値は `src/dress-up.ts` の `variants`（基本人物は `wardrobe-common.ts` の `baseAnchor`）、拡大率と座標の計算は `wardrobe-common.ts` の `drawPreview()` を参照する。`waist` は元PNG内の腰の基準点、`feet` は足裏の基準Y。元画像を変形保存せず、描画時に位置と大きさを調整する。数値を変更するときはソースを正とする。

画素密度や接地基準の統一方法は [#105](https://github.com/ot-nemoto/gladios/issues/105) の検討事項で、解決済みではない。

画像切替版で保存するPNGは位置合わせ後のCanvasではなく元画像。着脱版では、合成用Canvasの1086×1708のPNGを保存する。画像生成のAPIキーや、他サービスのログインは含まない。既存画像を表示するだけなら画像生成サービスは不要。

### 装備着脱版のパーツと座標

- 共通の兜なし人物は既存の `src/assets/dress-up/base.png` を参照する。
- `src/assets/equipment/body.png` は装備時の人物。首・襟足・肩を元画像から保持する。`ponytail.png` は低いポニーテール。両方1086×1448で、描画時にY=260へ配置する。
- 兜PNG6枚は1086×1708で位置・大きさを調整済み。Y=0に重ねる。金・一本角は最新の頭部サイズ微調整、黒赤は高い鶏冠を含む。このPNGに再度倍率を掛けない。
- 描画順はポニーテール→装備時の人物→兜。髪の高さは `equipment-data.ts` の `hairY`。外したときは元人物だけをY=260へ描画する。
- 表示位置は両ページの基本人物と腰・足裏を合わせる。着脱版は全候補で同じ倍率。保存対象は縮小前の合成結果。PNGは保存操作時だけ `toBlob()` で生成する。直前のBlob URLは次の保存時とページを離れる時に解放する。
- サムネイルは各兜パーツの角・羽飾りを含む範囲を切り出した128×128の透過PNG。余白を除いて中央に収める。「兜なし」は画像を使わず「—」を表示する。装備時の人物表示には元の兜付き全身画像6枚を使わず、共通人物と兜パーツを合成する。兜なしは `dress-up/base.png` をそのまま使う。
- パーツ候補は `equipment-data.ts` に追加すれば選択ボタンと件数へ反映される。`vite.config.ts` の2つのHTML入口を維持し、サブパスで両ページと相互リンクを確認する。

### 兜単体のサムネイルを再作成するとき

元にするのは `src/assets/equipment/` の兜PNG（人物を含む合成画像ではない）。ブラウザのCanvasで、アルファ値128以上の画素を含む最小矩形に元画像側の余白4pxを足す。出力は128×128、長辺108pxで縦横比を保ち、寸法と中央位置を四捨五入する。`imageSmoothingEnabled=false` で縮小し、周囲に最低10pxの透明余白を残す。共通寸法は `equipment-data.ts` の `equipmentThumbnailSize` と一致させる。

再現用のコード例（`npm run dev` で開いたページの開発者ツールで実行。関数の引数は兜PNGのファイル名。返されたCanvasから `toDataURL("image/png")` でPNGを保存できる）：

```js
async function helmetThumbnail(filename) {
  const image = new Image();
  image.src = `/src/assets/equipment/${filename}`;
  await image.decode();
  const source = document.createElement("canvas");
  source.width = image.naturalWidth;
  source.height = image.naturalHeight;
  const g = source.getContext("2d");
  g.drawImage(image, 0, 0);
  const pixels = g.getImageData(0, 0, source.width, source.height).data;
  let left = source.width, top = source.height, right = -1, bottom = -1;
  for (let y = 0; y < source.height; y++) for (let x = 0; x < source.width; x++) {
    if (pixels[(y * source.width + x) * 4 + 3] < 128) continue;
    left = Math.min(left, x); top = Math.min(top, y);
    right = Math.max(right, x); bottom = Math.max(bottom, y);
  }
  if (right < left) throw new Error("Empty helmet image");
  left = Math.max(0, left - 4); top = Math.max(0, top - 4);
  right = Math.min(source.width - 1, right + 4);
  bottom = Math.min(source.height - 1, bottom + 4);
  const width = right - left + 1, height = bottom - top + 1;
  const scale = 108 / Math.max(width, height);
  const w = Math.round(width * scale), h = Math.round(height * scale);
  const result = document.createElement("canvas");
  result.width = result.height = 128;
  const ctx = result.getContext("2d");
  ctx.imageSmoothingEnabled = false;
  ctx.drawImage(image, left, top, width, height,
    Math.round((128 - w) / 2), Math.round((128 - h) / 2), w, h);
  return result;
}
```

出力先は `thumbs/`。元画像→出力名は `silver-teal.png`→`silver.png`、`black-gold-purple.png`→`purple.png`、`gold-red.png`→`goldred.png`、`silver-horned.png`→`horned.png`、`gold-single-horn.png`→`goldhorn.png`、`black-red-crest.png`→`blackred.png`。作成後、角と羽飾りの欠け・画像の寸法・実際の選択欄での見た目を確認する。

### 全身画像の候補を1つ追加するときの確認箇所

これは拡張依頼があった場合の実装案内であり、追加自体は今回行わない。

1. 全身PNGと縮小サムネイルを、それぞれ上記ディレクトリへ追加する。
2. TSの画像import、`Style`、`styles`、`variants` を更新する。固有ID・名称・説明・代替テキスト・腰と足裏の基準を揃える。
3. ボタンのイベント処理にある `base / silver / purple / goldred / horned / goldhorn / blackred` の判定にも新IDを追加する。
4. HTMLの `button[data-style]` とサムネイルを追加し、`7 STYLES`・初期カウンター `02 / 07`、本文・メタ情報など件数を含む文言を確認する。TSの初回読込失敗時の `— / 07` も更新する。サムネイルの `img` の `width` / `height` は、その画像の縦横比と一致させる（現在は元PNGの寸法を指定）。
5. 他の画像とキャラクターの体格・服装・向き・絵柄・位置が揃うか比較する。現在の承認済み画像を参照し、未依頼の描き直しやエフェクト追加まで広げない。

全身PNGはTSからimportし、サムネイルはHTMLでViteが処理するパスを使っている。配信先の `/gladios/` を壊す固定URLを追加しない。

## 起動と確認

Node.js 24。リポジトリ、またはZIP展開後の `gladios/` で実行する。

```sh
npm ci
npm run dev
```

開発画面は画像切替版 `http://localhost:5173/` と着脱版 `http://localhost:5173/equipment.html`。型検査と通常ビルドは次の通り。

```sh
npm run typecheck
npm run build
```

GitHub Pagesのサブパスも確認する場合は、次のビルドでdistを置き換えてからpreviewを起動する。

```sh
npm run build -- --base=/gladios/
npm run preview -- --base=/gladios/ --host 127.0.0.1 --port 4173 --strictPort
```

確認URLは `http://127.0.0.1:4173/gladios/` と `http://127.0.0.1:4173/gladios/equipment.html`。ルートURLでの通常previewへ戻す際は、一度previewを停止し、`npm run build` で通常のdistを作り直してから `npm run preview` を起動する。ポート使用中なら別のポートを指定する。developへマージすると公開ワークフローが実行される。

検証結果の記録方法は [開発ガイド](development.md) を参照。装備室の基本確認の例は以下。

- 初期画像、全候補への切替、兜を外す、名称・選択表示が一致する。
- 保存したPNGが選択中の元画像と一致する。
- 素早く切り替えても古い読込結果へ巻き戻らない。
- 画像読込失敗時にエラーを表示し、直前の表示・保存先を維持する。初回失敗なら保存できず、再選択で再試行できる。
- TabとEnter/Spaceで操作でき、選択ボタンの `aria-pressed` とCanvasの説明が更新される。
- 狭い画面でも操作でき、Pages用ビルドで画像の404がない。

ブラウザ確認にはPlaywrightを利用できる。現時点でリポジトリにPlaywrightのテスト環境は同梱していない。表示済みのIDは `canvas.dataset.style` で確認できる。未検証事項は実施済みと扱わない。

[GitHubリポジトリ](https://github.com/ot-nemoto/gladios)のdevelopを開き、[依頼テンプレート](装備室_依頼テンプレート.md) に今回の変更を記入して渡す。作業環境にはGit・Node.jsが必要。PR操作にはGitHubの権限とgh、規定のレビューには認証済みClaude Codeが必要になる。`AGENTS.md` / `CLAUDE.md` の自動読込対応は環境によるため、依頼文にも読むファイルを明記している。

### ファイル添付を受け付けるWebチャット

下記の共有用ZIPと、記入済みの依頼テンプレートを渡す。ZIPを展開・読解できるかはそのサービスによる。まず変更案や差分を受け取り、リポジトリを操作できる環境で適用・確認する。ZIPにはGit履歴がないため、それだけで元リポジトリへのPRを作れるものではない。過去の経緯が必要ならGitHub上のIssue・PR・履歴も参照する。

共有用ZIPは、**共有したいコミットがHEADでありGitHubへpush済みであることを確認し、追跡済みの内容から**作る。未コミットの変更は含まれない。develop以外から共有する場合は、そのブランチ名またはPRのURLも伝える。

```sh
mkdir -p work/handoff
git archive --format=zip --prefix=gladios/ --output=work/handoff/gladios-wardrobe-handoff.zip HEAD
git rev-parse HEAD
```

コード・画像・資料・ロックファイルを含む。`.git`、`node_modules`、未追跡の添付ZIPや作業ファイルは含まれない。新たに認証情報を追加して共有しない。ZIPと一緒に出力されたコミットIDを伝えると、渡した時点を特定できる。

この資料の用意は、他サービスへの接続やアカウント権限の設定まで行うものではない。拡張したい内容は、次の依頼で小さく指定する。
