# 確認記録：基準間合いによる部位の自動選択と移動（設計書 v3.44、Issue #6）

記録日：2026-11-16

## 変更（v3.44）
- 部位の自動選択は、部位ごとに「その部位を狙う一式の基準間合いに立った場合」で採点する（相手の姿勢は判断時点）。基準間合いの位置が移動範囲の外なら、端に立った場合で採点する。
- 攻撃する部位が決まったら（指定・自動とも）、足裏の間隔が基準間合い ±0.02m の外なら基準間合いへ移動（遠ければ接近、近ければ距離を取る）してから攻撃する。移動範囲の端に背を付けて下がれないときは、その位置から攻撃する。
- 接近・距離を取るは目標の間隔を越えずに止まる（以前は 1 歩 0.009m 刻みで約 0.01m 行き過ぎていた）。
- 同点時の固定順を 胴体＞頭部＞脚＞腕 に変更（以前は 胴体＞頭部＞腕＞脚）。
- グラディウスの攻撃 24 一式にも基準間合い（振りテストの値）を付けた（build_keyframes_full.py）。
- 試作の確認用の固定分岐で、「間隔 1.5m 以上なら接近（ルール3）」は攻撃しない側（ダミー）だけに適用。攻撃する側の間合いは基準間合いに従う。
- 確認シナリオ「戦闘4（接近距離0.9m）」は廃止（攻撃は基準間合いから行うため、近距離の攻撃は起きない）。

## 原因（変更前）
- グラディウスの斬り・脚狙いで、盾より先に脚に触れるのは間隔 1.40〜1.45m だけ（振りテスト、基準間合い 1.42m）。
- グラディウスの一式には基準間合いがデータになく、試作は既定の接近先 1.40m で止まる。実際には行き過ぎて 1.39m で止まり、脚の軌道が先に盾に当たる扱い（脚 20 点）になって頭部が選ばれ、大盾で毎回止められた（斬る・鏡合わせで命中 0、防がれた 112）。

## 検討して採らなかった案
- 基準間合いへ移動できない部位を候補から外す案（PR #29 の最初の実装）：移動範囲の端に追い詰められると全部位が外れ、攻撃しなくなった（トライデント自動で接触 0 回）。端に立った場合で採点する形に改めた（ユーザーの決定）。
- 防御の薄さを、相手の構えに加えて相手の盾で取りうる防御姿勢（防御一式の中央の姿勢）でも採点し、最も厚い評価を使う案：防御姿勢で止まった相手には斬撃はどの部位も盾が先（0 点）になり、全部位が同点で頭部が選ばれた。実戦では脚に届く瞬間にはまだ盾が下りきっていないため、悲観的すぎた。攻撃が届く瞬間の相手の姿勢を予測して採点する案は #27 に残した。

## 所見
- 斬る・鏡合わせは、両者が脚を選び 82.73 秒で決着（両者同時に体力 0 のため、終了判定の順で B の勝ち。#10）。v3.37 時点の記録（両者が脚を選んで決着）と同じ形に戻った。
- すね当てなしは、B への脚の命中が E=45 になるが、ダメージ段階は「通常」（20〜49）のままで鏡合わせと同じ結果になった。
- 悪くなったシナリオ：スィカ自動（109.44 秒で決着 → 決着せず）、盾押し＋脚攻撃（36.69 秒 → 決着せず）、戦闘5（33.43 → 49.25 秒）、戦闘9（34.57 → 100.93 秒）。いずれも、両者の狙う一式の基準間合いが違う（例：A の脚 1.42m、B の胴 1.60m）。
- 基準間合いの違う同士（トライデント・ハスタ対グラディウスなど）は、一方が下がり一方が寄る「間合いの取り合い」で移動範囲の端まで寄る。端に背を付けた側はその位置から攻撃する（トライデント自動で接触 56 回）が、決着はしない。盾押し＋脚攻撃も、押し込んだ後に脚の間合いまで下がる間に相手が立て直し、決着しなくなった。作戦ルール（#7）で扱う（#26）。
- 自動選択が脚狙いの突きを選ぶようになり、その一式で足首が地面より下に入ることが表に出た（プギオで 4.5cm）。判定には影響しない（#28）。
- 決定論：同じ条件の再実行でログが完全一致。TS の移植は全 24 シナリオで Python と完全一致。
