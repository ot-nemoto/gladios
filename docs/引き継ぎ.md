# 引き継ぎ資料

Claude・他のLLMなどへ、Gladios（キャラと背景の合成アプリ）の変更を依頼するための実装案内。開発規則の正本は [development.md](development.md)。決定事項は [基本設計書](01_基本設計書.md) の本文を読む。この資料は新しい機能の採用を決めるものではない。

## 現在できること

[公開ページ](https://ot-nemoto.github.io/gladios/)はトップの1ページだけで、キャラと背景を1つずつ選んで重ね、512×512のPNGとして保存できる。キャラ・背景の一覧、初期表示、選択欄の表示は [基本設計書 §2](01_基本設計書.md#2-現在の仕様) を参照。

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `index.html` | 合成アプリのページ（見出し、プレビューのCanvas、キャラ・背景の選択欄、保存ボタン） |
| `src/scene.ts` | 選択欄の生成、Canvasでの合成、PNG保存、サムネイルの段階的な読み込み |
| `src/scene.css` | レイアウトと画面幅への対応、選択欄の横スクロール |
| `src/scene-data.ts` | キャラ・背景の候補（id・表示名・素材）と、縮小画像の対応 |
| `src/common.ts` | 要素の取得（`required`）と、キャッシュ付きの画像読み込み（`loadImage`） |
| `src/assets/scene/` | キャラ（背景透過の可逆webp）と背景（webp）。いずれも512×512 |
| `src/assets/scene/thumbs/` | 選択欄用の縮小画像（256×256のwebp、ファイル名は素材の `id` と同じ） |
| `package.json` / `package-lock.json` | コマンドと依存関係 |
| `vite.config.ts` / `tsconfig.json` | ViteとTypeScriptの設定 |
| `.github/workflows/deploy-github-pages.yml` | developへのpush後、GitHub Pagesへ公開 |

## 合成と保存

- Canvas（512×512）に背景、キャラの順で、拡大・縮小せずに描く。素早く選び直したときは、最後に選んだ組み合わせだけを表示する。
- 画像の読み込みに失敗したら、直前の表示と保存対象を保ち、エラーを表示する。初回に失敗した場合は保存できず、選び直すと再試行する。
- PNGは保存操作のときだけ `toBlob()` で作る。直前のBlob URLは、次の保存時とページ離脱時に解放する。
- 表示中の組み合わせは、Canvasの `data-character` / `data-background` で確認できる。

## 素材

### キャラ・背景を追加・差し替えるとき

1. 512×512の素材を `src/assets/scene/<id>.webp` に置く。キャラは背景透過の可逆webp（ファイルの画素を変えずに軽くするため。ブラウザでは半透明の縁がPNGと最大1階調変わることがある）。PNGなどで受け取ったキャラは、透明部分のRGBも保つ `exact=True` の可逆webpに変換してから置く。ファイル名は `scene-data.ts` の `id` と同じにする。背景は、選んだときの読み込みを軽くするため webp（画質90）で置く。PNGなどで受け取った背景は変換してから置く。

```python
from PIL import Image

# キャラ（可逆・透過あり）。受け取ったファイルが 8bit の RGBA PNG で、色の補正情報を持たないことを先に確かめる。
# 16bit や色の補正情報（カラープロファイル・ガンマ）付きのPNGは、変換で画素や色が変わるため止めてユーザーに相談する。
src = "<受け取ったキャラ>.png"
header = open(src, "rb").read(26)
assert header[:8] == b"\x89PNG\r\n\x1a\n" and header[24] == 8 and header[25] == 6, "8bit の RGBA PNG ではない"
im = Image.open(src)
assert not {"icc_profile", "gamma", "chromaticity"} & im.info.keys(), "色の補正情報がある"
im.save("src/assets/scene/<id>.webp", "webp", lossless=True, exact=True, method=6, quality=100)
assert Image.open("src/assets/scene/<id>.webp").convert("RGBA").tobytes() == Image.open(src).tobytes()

# 背景（画質90）
Image.open("<受け取った背景>.png").convert("RGB").save("src/assets/scene/<id>.webp", "webp", quality=90, method=6)
```

2. `src/scene-data.ts` に素材のimportと、`characters` または `backgrounds` への1行（`id`・表示名・`src`）を追加する。
3. 選択欄用の縮小画像 `src/assets/scene/thumbs/<id>.webp` を作る。合成と保存には元画像を使い、縮小画像は選択欄だけで使う。縮小画像がないと、選択欄に元画像がそのまま使われ（読み込みが重くなる）、コンソールに `Missing scene thumbnail: <id>` が出る。素材を差し替えたときも、縮小画像を作り直す（古い縮小画像のままだと、選択欄だけ古い絵になる）。作成例（Pillow）：

```python
from PIL import Image
# 背景は、画質90に変換する前の受け取った元画像から作る。
# キャラは、可逆webpの画素が元画像と同じため、src/assets/scene/<id>.webp から作ってよい。
src = "<受け取った背景>.png"  # キャラなら "src/assets/scene/<id>.webp"
im = Image.open(src)
im = im.convert("RGBA") if im.mode in ("RGBA", "LA", "P") else im.convert("RGB")
im.resize((256, 256), Image.BOX).save("src/assets/scene/thumbs/<id>.webp", quality=85)
```

4. README と基本設計書 §2 の一覧（種類の数を含む）を更新する。

### サムネイルの読み込み

選択欄のサムネイルは `src/scene.ts` で段階的に読み込む。`img` の `src` は最初は空で、URLを `data-src` に持ち、次のどれかで `src` に移す。

1. 欄ごとの IntersectionObserver（`root` は欄の要素、`rootMargin: "0px 100%"`）。欄のスクロール位置で見えている範囲と、左右に欄の幅1つ分の先までをすぐに読む。`root` を欄にしているため、画面外にある欄でも先頭の数枚は最初に読む。
2. 欄の最初の `scroll` イベント。その欄の残りをすべて読み始め、読み込み途中に素早くスワイプしても空欄が長く残らないようにする。
3. ページの `load` 後の `requestIdleCallback`（未対応なら `setTimeout`）。残りを `fetchPriority = "low"` で2枚ずつ（`thumbBatchSize`）読み、前の2枚が読み終わってから次へ進む。プレビューの元画像を読み込んでいる間（canvas に `aria-busy` がある間）は止める。

読み込みを始めたサムネイルは IntersectionObserver の監視から外す。IntersectionObserver のないブラウザでは、従来どおり最初にすべて読む。`loading="lazy"` は横スクロール欄では先読みが足りず空欄が見えるため使わない。

## 起動と確認

Node.js 24。リポジトリ、またはZIP展開後の `gladios/` で実行する。

```sh
npm ci
npm run dev
```

開発画面は `http://localhost:5173/`。型検査と通常ビルドは次の通り。

```sh
npm run typecheck
npm run build
```

GitHub Pagesのサブパスも確認する場合は、次のビルドでdistを置き換えてからpreviewを起動する。

```sh
npm run build -- --base=/gladios/
npm run preview -- --base=/gladios/ --host 127.0.0.1 --port 4173 --strictPort
```

確認URLは `http://127.0.0.1:4173/gladios/`。ルートURLでの通常previewへ戻す際は、一度previewを停止し、`npm run build` で通常のdistを作り直してから `npm run preview` を起動する。ポート使用中なら別のポートを指定する。developへマージすると公開ワークフローが実行される。

検証結果の記録方法は [開発ガイド](development.md) を参照。基本の確認の例は以下。

- 初期表示（TADALA×海）、全キャラ・全背景への切り替えで、表示と名前・選択表示が一致する。
- 全組み合わせで、保存したPNGが素材を重ねた画像と一致する（Canvasの画素を比べる）。
- 素早く切り替えても古い読み込み結果へ巻き戻らない。読み込み失敗時の動きが上記のとおり。
- TabとEnter/Spaceで操作でき、選択ボタンの `aria-pressed` とCanvasの説明が更新される。
- 320px・390px・760px・761px・1200px幅などで、選択欄が1行の横スクロールのまま、名前がボタン内に収まり、ページが横にはみ出さない。Pages用ビルドで画像の404がない。

ブラウザ確認にはPlaywrightを利用できる。リポジトリにPlaywrightのテスト環境は同梱していない。未検証事項は実施済みと扱わない。

## 他のLLMへの渡し方

### リポジトリを開けるエージェント

[GitHubリポジトリ](https://github.com/ot-nemoto/gladios)のdevelopを開き、[依頼テンプレート](依頼テンプレート.md) に今回の変更を記入して渡す。作業環境にはGit・Node.jsが必要。PR操作にはGitHubの権限とgh、規定のレビューには認証済みClaude Codeが必要になる。`AGENTS.md` / `CLAUDE.md` の自動読込対応は環境によるため、依頼文にも読むファイルを明記している。

### ファイル添付を受け付けるWebチャット

下記の共有用ZIPと、記入済みの依頼テンプレートを渡す。ZIPを展開・読解できるかはそのサービスによる。まず変更案や差分を受け取り、リポジトリを操作できる環境で適用・確認する。ZIPにはGit履歴がないため、それだけで元リポジトリへのPRを作れるものではない。過去の経緯が必要ならGitHub上のIssue・PR・履歴も参照する。

共有用ZIPは、**共有したいコミットがHEADでありGitHubへpush済みであることを確認し、追跡済みの内容から**作る。未コミットの変更は含まれない。develop以外から共有する場合は、そのブランチ名またはPRのURLも伝える。

```sh
mkdir -p work/handoff
git archive --format=zip --prefix=gladios/ --output=work/handoff/gladios-handoff.zip HEAD
git rev-parse HEAD
```

コード・画像・資料・ロックファイルを含む。`.git`、`node_modules`、未追跡の添付ZIPや作業ファイルは含まれない。新たに認証情報を追加して共有しない。ZIPと一緒に出力されたコミットIDを伝えると、渡した時点を特定できる。

この資料の用意は、他サービスへの接続やアカウント権限の設定まで行うものではない。変更したい内容は、次の依頼で小さく指定する。
